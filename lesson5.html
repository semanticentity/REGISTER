One Sound, Every Voice

All five voices keep the same kind of settings. Line them up in a row, and one formula finds any of them, and one description of a sound fits them all.

In this lesson (about 15 minutes, sound on). You will be able to:
  • find any voice's envelope field with one formula
  • explain what a pointer is by moving one from voice to voice
  • load one sound onto two voices and hear them blend
You will use what lessons 1 to 4 taught: addresses, POKE, octaves, and the envelope struct.
It keeps playing while you scroll.

Hear it: two voices, one tune

Press PLAY. The melody from lesson 3 is back, twice: the lead plays it, and the bass plays it two octaves lower, the way you set it up in lesson 3. Playing the same part on two voices at once is doubling. more Doubling an octave or two apart is one of the oldest tricks there is, in orchestras and in pop.

Right now the two voices sound like two different instruments. The lead is plucked and short. The bass uses the chip's default shape. Press MATCH THEM to give both the same envelope, then UNMATCH to hear the difference again.

When they match, the two voices fuse into one bigger sound. A saved set of settings that makes a sound, ready to load onto any instrument, is a patch. more The name comes from early synthesizers, where you made a sound by connecting parts with patch cables. MATCH THEM loaded one patch onto two voices. This lesson is about how that can work.

Five structs in a row

Every voice has an envelope struct like the lead's in lesson 4. The five sit back to back starting at $1060: kick, snare, lead, bass, noise. The same kind of thing repeated back to back is an array. more

Each struct in the row is one element of the array. more An element's position, counted from 0, is its index. more Here the index is the voice number: kick 0, snare 1, lead 2, bass 3, noise 4.

Each element is 4 bytes, so element number i starts 4 × i bytes into the array. That gives one formula for any field of any voice:

address = $1060 + index × 4 + offset

lead attack   $1060 + 2 × 4 + 0  =  $1068
bass attack   $1060 + 3 × 4 + 0  =  $106C
noise release $1060 + 4 × 4 + 3  =  $1073

That is where lesson 4's $1068 came from: the lead is element 2, so its struct starts 8 bytes in.

A pointer picks the voice

Pick a voice below and move a slider. The sum under each slider is worked out in front of you.

Notice what changes when you pick another voice: one number, the base address of the struct you are editing. The offsets never move. A value that holds an address, so code can work on whatever is stored there, is a pointer. more The voice picker is a pointer. Point it at $106C and the same four sliders edit the bass instead of the lead.

Same index, other arrays

Envelopes are not the only setting every voice has. Volume is another array, one byte per voice, starting at $10B0. A 0 means "not set", which plays at full volume. 1 to 127 sets a level, from very quiet to full. The voice number is the index here too:

lead volume   $10B0 + 2  =  $10B2
bass volume   $10B0 + 3  =  $10B3

One index, many arrays. A voice is really just a number that picks one element out of each table.

Names instead of addresses

Working out addresses by hand is slow and easy to get wrong. So REGISTER lets you write a patch with field names, and the voice you load it on supplies the base address. A program that turns names like these into the addresses and numbers a machine runs is a compiler. more A compiler for C, one of the oldest programming languages still in wide use, does the same with a struct: you write voice.attack, and it works out base plus offset for you.

Press SHOW AS POKES with the lead, then with the bass. Same names, different addresses. The compiler did the base-plus-index sums. Then APPLY the patch to both.

Hear it again

Listen now. The lead and the bass play the same patch, two octaves apart, and they blend like one instrument with a deep bottom. That is doubling done with data: one description of a sound, written into two places in memory, found with one formula.

It is also why a patch from the sequencer's sound menu works on any voice. Every voice has the same struct layout, so the field names always mean the same offsets. Only the index changes.

Check yourself

In a doubled part, the lower voice is often kept a little quieter so it supports the tune instead of covering it. Set the bass's volume to 40 with one POKE. Work out the address from the volume array first.

Now answer these out loud before you open them.

Where is the noise voice's release byte?

$1073: $1060 + 4 × 4 + 3. It is the very last byte of the array. See "Five structs in a row".

When you move the pointer to another voice, what changes and what stays the same?

The base address changes. The offsets, and the layout of the struct, stay the same. See "A pointer picks the voice".

Where is the snare's volume?

$10B1: the snare is index 1, and each volume element is 1 byte. See "Same index, other arrays".

Why can one patch load onto any voice?

Every voice uses the same struct layout, so each field name means the same offset everywhere. The compiler only has to change the base address. See "Names instead of addresses".
