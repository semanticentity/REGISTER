REGISTER

A memory-mapped audio primitive. 217-byte core. Infinite leverage.

Sound is memory. Memory is bytes. Bytes are yours. POKE $1000, hear kick. That's it. That's the language.

Philosophy: Tiny core, explicit extensions. Like htmx: extend HTML, don't replace it. REGISTER extends memory, doesn't hide it. A student's first program is 2 lines. ADSR, tuning, effects load as packs when you need them.

Core Concept

REGISTER is a memory-mapped audio coprocessor. Write bytes to addresses, hear sound. No API, no drivers, no abstraction.

; Make a kick drum
POKE $1000, 1      ; gate ON at step 0
POKE $1500, 3      ; start sequencer
; That's it. Kick plays.

The core is 217 BYTES of registers. A full song fits in a tweet.

Memory Map

Audio lives at $1000-$1FFF. Everything is a byte. The core is 217 bytes inside $1000-$15FF, and packs fill the rest.

Design Rules

A REGISTER song is like a vector image: a description, not a recording. Each machine plays it at whatever quality it can. Three rules keep that true as the spec grows.

1. One map, no overlaps

Every address belongs to exactly one region, listed in memory-map.json. tools/check-map.js fails if two regions overlap or if any code writes to unassigned space. Two features sharing an address is how a pack ends up silently changing another one.

2. Unknown regions are ignored, not errors

A machine that doesn't implement a pack skips its bytes and plays the rest. A $5 microcontroller that only knows the core still plays a song written for the full sequencer, just without the effects.

3. Machines declare what they can do

Each machine writes a bitmask to CAPS at $15F0-$15F3: bit 0 is the core, and each pack has its own bit (see memory-map.json). SPEC_VERSION at $15F4 says which version of the map it follows. Read them to know what a song will sound like on that machine. All 32 bits are taken, so newer packs go in a second word, CAPS_EXT at $15F5, the way CPUs added extended CPUID leaves. A machine that predates it reads 0 there, which is true: it has none of them.

; Does this machine have effects? (XFX is bit 3)
LB   t0 $15F0
ANDI t0 8
JZ   no_effects

Primitives

Everything in REGISTER reduces to these primitives:

BYTE8 bits. 0-255 unsigned, or -128 to +127 signed (two's complement).
ADDRESS16-bit pointer into memory. Written as $XXXX hex.
GATE0 = silent, >0 = trigger. For melodic voices, value = MIDI note.
STEPOne of 16 positions (0-F). Sequencer reads gates at each step.
TICKOne step advance. Rate = 60/BPM/4 seconds (16th notes).
VOICESound generator. 5 total: kick, snare, lead, bass, noise.
PATTERN16 bytes of gate data. One pattern per voice.

WASM Mapping

REGISTER compiles to WebAssembly. Memory-mapped addresses become WASM linear memory.

;; WASM memory layout (64KB page)
(memory (export "memory") 1)

;; Address constants
(global $KICK_GATE i32 (i32.const 0x1000))
(global $SEQ_CTRL  i32 (i32.const 0x1500))
(global $SEQ_TEMPO i32 (i32.const 0x1501))

;; Read/write primitives
(func $read (param $addr i32) (result i32)
  (i32.load8_u (local.get $addr)))

(func $write (param $addr i32) (param $val i32)
  (i32.store8 (local.get $addr) (local.get $val)))

Syscalls / Imports

WASM imports audio triggers from the host. The host handles synthesis.

;; Host must provide these
(import "audio" "triggerKick"  (func (param i32)))           ; pitch
(import "audio" "triggerSnare" (func (param i32 i32)))       ; tone, snap
(import "audio" "triggerLead"  (func (param i32)))           ; note
(import "audio" "triggerBass"  (func (param i32 i32)))       ; note, fm
(import "audio" "triggerNoise" (func (param i32)))           ; decay

Tick Cycle

// Host calls tick() at BPM rate
setInterval(() => {
  if (wasm.tick()) {           // returns 1 if playing
    updateUI(wasm.getStep());
  }
}, (60 / bpm / 4) * 1000);     // 16th note interval

Division of labor:

  • WASM: sequencer state, memory, step logic
  • Host: timing, audio synthesis, UI

Song Structure

A pattern is one bar. A song is bars in order: an intro, a drop, a loop. The arranger (the XSong pack) plays that order, and it works the way a CPU does.

Write it

Everything before the first time marker sets up the song. Everything after happens at a point in time.

# setup: patterns and scenes
@pattern four "x...x...x...x..."
@pattern back "....x.......x..."
@scene intro
  kick: four
@scene full
  kick: four
  snare: back

# timeline
@at 0          ; bar 1
@play intro
@at 2b         ; bar 3 ("b" = bars, or give steps: @at 32)
@play full
@tempo 124
@loop start
> 4b           ; 4 bars later (same as @after 4b)
@loop end      ; jump back to @loop start

Also in the timeline: @poke, @swing, @stop, and @wait 16 (same as @after 16).

What it compiles to

No new machinery. The song becomes bytes in memory, and the chip runs them.

AddressSizeFunction
$17602SONG_POS: song position in steps. The chip adds 1 every step.
$17621SONG_CTRL: bit 0 = arranger on
$17631SONG_COUNT: events in the table (max 24)
$1770144SONG_EVENTS: 24 events, 6 bytes each
$1800256SONG_BANK: 16 stored patterns (slot 0 is silence)

Each event says at step N, do this: step low byte, step high byte, op, then three arguments.

OpNameDoes
1POKEWrite a byte to an address (tempo, swing, anything)
2COPYCopy a stored pattern into a voice (how a scene changes)
3JUMPSet the song position (how a loop works)
4STOPClear SEQ_CTRL

The lesson

Look at @loop end. It compiles to one JUMP event, which writes a new value into SONG_POS. That's all a loop is, here and in every CPU: something rewrites the position counter, and execution carries on from there. A for loop, an if, a function call are all versions of this one move.

The arranger is a tiny computer inside the chip, with four instructions and a program counter. Students can read a song's event table in the debugger and run it by hand.

A machine without XSong (its CAPS bit 29 is clear) ignores the table and plays the song's first section. That's rule 2 at work.

Sound Design

A sound is a short text that sets fields by name. A = 140 means the lead's attack at $1068 on the lead and the bass's attack at $106C on the bass. The voice is the base pointer; the sound is the struct.

SOUND Slow Pad
A = 140        ; attack
S = 200        ; sustain
VOL = 90
UNISON_SPREAD = 18   ; only lead and bass have this

Load it on any voice. What every voice has always lands. What only some voices have lands where it exists and is skipped with a reason elsewhere. FM, SID and speech settings are one shared patch per chip, so they only apply when the voice is on that engine.

Teaches: structs and base addresses, relative versus absolute addressing, compiling (AS POKES lowers names to addresses), and graceful degradation.

Extending REGISTER

The newer packs follow the same pattern. XWAVE ($1A20) is a waveform as 32 signed bytes, played by the wave engine. XPOKEY ($1A50) is the Atari's chip: pitch is a clock divided by a byte, so at 64 kHz high notes come out a little sour. XBUS ($1508) turns on a bus budget: only so many automation writes fit in a step, and the rest drop, corrupt, run late or land at the wrong address. XSEQ parameter locks ($1E00) change one byte on one step, then put it back. And any HTML instrument can join: tools/map-from-html.js drafts a map from its controls, and dom-bridge.js keeps the bytes and the controls in step both ways. WHITE DWARF was the first port.

The spec is minimal by design. Extension points:

Add a Voice

; Claim free space: $1F30-$1FFF is yours
$1F40: gate[16]    ; trigger pattern
$1F50: param1[16]  ; voice-specific

; Add import to WASM
(import "audio" "triggerMyVoice" (func (param i32 i32)))

Add Effects

; Effects live in the XFX pack, $1080-$109F
$1080: FX_FILTER_TYPE    ; 0=off, 1=LP, 2=HP, 3=BP, 4=notch
$1081: FX_FILTER_CUTOFF  ; 0-255
$1092: FX_DELAY_FEEDBACK ; 0-255
$1093: FX_DELAY_MIX      ; 0-255 dry/wet

Longer Patterns

; Longer patterns live in the XSteps pack, $1600-$16FF
; 1-128 steps per voice, polyrhythms

Embed in Your App

// Minimal embedding
const mem = new Uint8Array(65536);
const KICK = 0x1000;

mem[KICK + 0] = 1;  // step 0: kick
mem[KICK + 4] = 1;  // step 4: kick

// Your tick loop
function tick(step) {
  if (mem[KICK + step]) playKick();
  if (mem[SNARE + step]) playSnare();
  // ...
}

Example: XEnv Pack (ADSR)

; Lead voice: slow attack pad sound
POKE $1068, 200        ; A = slow attack (~800ms)
POKE $1069, 50         ; D = short decay
POKE $106A, 180        ; S = high sustain (70%)
POKE $106B, 150        ; R = medium release (~600ms)

; Bass voice: punchy pluck
POKE $106C, 5          ; A = instant attack
POKE $106D, 80         ; D = medium decay
POKE $106E, 50         ; S = low sustain (20%)
POKE $106F, 40         ; R = quick release

; Each value 0-255, scaled by synth (typically /255 * max_time)

Example: XTuning Pack

; Switch to Just Intonation
POKE $10A0, 1          ; mode = JUST

; Or try Colundi (47 non-12TET frequencies)
POKE $10A0, 3          ; mode = COLUNDI

; 432 Hz tuning (A4 = 432 instead of 440)
POKE $10A1, $B0        ; low byte of 432
POKE $10A2, $01        ; high byte

; Detune lead +7 cents, bass -7 cents (instant thickness)
POKE $10A5, 135        ; lead: 128+7 = 135
POKE $10A6, 121        ; bass: 128-7 = 121

Example: XTempo Pack

; 16-bit BPM for extreme tempos
$1700: TEMPO_LO        ; Low byte
$1701: TEMPO_HI        ; High byte

; 300 BPM = $2C + ($01 * 256)
POKE $1700, $2C        ; 44
POKE $1701, $01        ; 256
; Total: 44 + 256 = 300 BPM

Example: XEuclidean Pack

; E(k,n) = distribute k hits across n steps
; Famous rhythms from GCD math:

E(3,8)  = x..x..x.    ; Cuban tresillo
E(5,8)  = x.xx.xx.    ; Cinquillo
E(5,16) = x..x..x..x..x...  ; Bossa nova
E(7,16) = x.x.x.xx.x.x.x..  ; West African

; Set kick to E(5,16):
POKE $1B00, 5          ; 5 hits
POKE $1B01, 16         ; 16 steps
POKE $1B0F, 1          ; enable

Example: XFollow Pack (from Ableton Live)

; After 4 plays, 70% chance jump to random slot
POKE $1C01, 4          ; play 4 times
POKE $1C02, 3          ; action = random
POKE $1C03, 70         ; 70% chance
POKE $1C00, 1          ; enable for kick

Example: XPatch Pack (from Max/MSP)

; Route LFO output to filter cutoff
POKE $1D10, $46        ; source = LFO1_VALUE ($1B46)
POKE $1D11, $1B
POKE $1D12, $81        ; dest = FX_FILTER_CUTOFF ($1081)
POKE $1D13, $10
POKE $1D14, 64         ; unity gain
POKE $1D00, 1          ; 1 patch active
