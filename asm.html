REGISTER ASM

Playing REGISTER from x366, the assembly language of the MTMC-16. No new instructions.

The chip watches memory. A MOV is a POKE. x366 stays as it is. The sound is in the bytes.

Where the chip lives

An x366 program picks its memory size with .MEMORY. REGISTER sits at 0x1000-0x1FFF, so a program that plays it asks for 16K:

AddressWhat
0x0000-0x001FProgram header
0x0020-0x0FFFCode and data (must end below 0x1000)
0x1000-0x1FFFREGISTER: the core at 0x1000-0x15FF, packs above it
0x2000-0x3FFFFree memory, then the stack, growing down from 0x4000

Why not 8K? At 8K the stack starts at 0x2000 and grows down into the chip. A program with no calls gets away with it. One with calls overwrites the song.

Writing to the chip

These are ordinary x366 instructions. Nothing here is new.

x366What it does to the chip
MOV [0x1000], 1Store one byte (0-255): kick on at step 0
MOV [0x1501], ALStore the low byte of a register: set the tempo
MOV [BX], ALStore a byte where BX points: walk a pattern with a pointer
MOV AL, [0x1502]Read a byte: which step the chip is on

Store bytes, not words. x366 is big-endian, so MOV [addr], AX writes the high byte first. REGISTER's few 16-bit fields (the A4 reference, the song position) are low byte first. Byte stores are always right.

Examples

Four on the floor

.MEMORY 16K

main:
    MOV [0x1000], 1     ; KICK_GATE[0]
    MOV [0x1004], 1     ; KICK_GATE[4]
    MOV [0x1008], 1     ; KICK_GATE[8]
    MOV [0x100C], 1     ; KICK_GATE[12]
    MOV [0x1501], 120   ; SEQ_TEMPO
    MOV [0x1500], 3     ; SEQ_CTRL: play and loop

hold:
    JMP hold         ; the chip plays on its own; press quit to stop

This is what the compiler emits for any song: every byte in address order, then SEQ_CTRL last so nothing plays half loaded.

The same beat with a pointer and LOOP

    MOV BX, 0x1000    ; BX points at KICK_GATE[0]
    MOV CX, 4         ; four hits
    MOV AL, 1
place:
    MOV [BX], AL       ; gate on
    ADD BX, 4         ; every fourth step
    LOOP place        ; CX = CX - 1, repeat until 0

Teaching: a pattern is an array, a step is an index, and BX is a pointer. Change the 4 in ADD BX, 4 and you hear the stride.

Euclidean rhythm, E(5,16)

; Spread 5 hits over 16 steps as evenly as integers allow (Bresenham)
    MOV BX, 0x1000    ; KICK_GATE[0]
    MOV CX, 16        ; 16 steps
    MOV DX, 0         ; error
    MOV AL, 1
step:
    ADD DX, 5         ; error += hits
    CMP DX, 16
    JL next           ; error below 16: no hit here
    SUB DX, 16        ; error -= steps
    MOV [BX], AL       ; hit
next:
    INC BX
    LOOP step

Teaching: the same integer trick draws a straight line on a pixel grid. Here it places drum hits.

Copy the kick onto the snare

    MOV SI, 0x1000    ; KICK_GATE
    MOV DI, 0x1020    ; SNARE_GATE
    MOV CX, 16
copy:
    MOV AL, [SI+0]
    MOV [DI+0], AL
    INC SI
    INC DI
    LOOP copy

Proposal: sound in the MTMC-16 emulator

Everything above assembles and runs on the MTMC-16 today. The bytes land in memory, but nothing plays them yet. To make sound, the emulator would need:

  1. A host for the chip. Pass writes to 0x1000-0x1FFF to REGISTER's 1,291-byte WebAssembly core (wasm-host.js), the way the emulator already maps VRAM. Or give the chip a window outside RAM, like VRAM, so it works at every .MEMORY size. Then only the compiler's base address changes.
  2. Maybe two syscalls. Everything else is memory, but these two need the host:
CodeNameArgumentsReturnsDescription
22WAIT_STEP-AX=stepBlock until the sequencer reaches the next step
23TRIGGERAX=voice (0-4)-Play a voice now, outside the pattern

With WAIT_STEP, a program can follow the beat, like recording hits live:

record:
    SYSCALL WAIT_STEP    ; AX = the step that just started
    MOV BX, AX
    ADD BX, 0x1020    ; SNARE_GATE[step]
    ; ...read a key; if one was pressed:
    MOV AL, 1
    MOV [BX], AL       ; record the hit on this step
    JMP record

This part is a proposal. Syscall numbers 22 and 23 are simply the next free codes; the MTMC-16's own docs decide.

The SNES worked this way too: its sound CPU made music by writing the DSP's registers. No sound instructions. Bytes at known addresses.
